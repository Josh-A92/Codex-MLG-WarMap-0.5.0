# Union Registry Persistence Contract

## Purpose

Define the storage-neutral version 1 snapshot contract for the global, user-managed Union Registry.

Union identities are shared reference data. They are not season rules and are not duplicated into season-scoped strategic envelopes.

## Authority and scope

Version 1 persists the complete canonical Union Registry:

- stable union identity;
- current display name and tag;
- aliases;
- default presentation colour;
- structured presentation metadata;
- current or archived registry status.

The registry does not contain:

- server or season relations;
- native or active status;
- ownership;
- combat strength;
- evidence or review records;
- calculated territory values;
- authentication or authorization state.

## Logical storage identity

Version 1 defines one current registry envelope for the application:

```text
union-registry / global
```

The logical identity is independent of season and server.

## Canonical version 1 envelope

```json
{
  "schemaVersion": 1,
  "savedAt": "2026-07-30T23:00:00.000Z",
  "identities": [
    {
      "unionId": "union-0001",
      "displayName": "Moonlight Guillotine",
      "tag": "MLG",
      "aliases": [],
      "defaultColor": "#8FCEFF",
      "presentationMetadata": {
        "emblem": "crescent-blade"
      },
      "registryStatus": "current"
    }
  ]
}
```

## Validation

- `schemaVersion` must equal integer `1`.
- `savedAt` must use canonical `YYYY-MM-DDTHH:mm:ss.sssZ` UTC form.
- `identities` must be an array.
- Top-level and identity fields are strict; unknown fields fail validation.
- Every identity contains all seven canonical fields.
- IDs, names, tags, and aliases are non-empty and non-whitespace.
- Aliases are unique case-insensitively within an identity.
- `defaultColor` is a `#RRGGBB` value.
- `presentationMetadata` is structured JSON-compatible data.
- `registryStatus` is exactly `current` or `archived`.
- `unionId` values are globally unique.
- The complete candidate list must also pass Union Registry Service construction.
- Validation and restoration are atomic.

## Serialization and restoration

- Serialization calls `listUnionIdentities({ includeArchived: true })`.
- Archived identities are never omitted from persistence.
- Serialization and deserialization return safe copies.
- `savedAt` is generated by orchestration through an injected clock.
- A missing envelope is a normal first-run state and leaves the bundled registry active.
- A valid stored envelope replaces the bundled registry as one complete candidate.
- Invalid storage leaves the current registry unchanged.
- Restoration creates a new Union Registry Service; it does not mutate or merge into the existing service.
- The strategic runtime must be composed only after the selected registry has been restored.

## Hosted evolution

The envelope is a local portability and restoration contract. A hosted implementation may normalize identities into database records, but must preserve:

- stable IDs;
- archive rather than destructive deletion;
- strict canonical validation;
- reference integrity from season-scoped records;
- version-aware writes and conflict reporting;
- authenticated actor and audit metadata outside this snapshot envelope.

The hosted API exposes explicit registry operations such as create, update, archive, and restore. Clients do not replace the whole shared registry directly.

## Current transition

`data/unions.json` remains the bundled first-run registry seed. Once persistent registry storage is integrated:

1. attempt to load the global registry envelope;
2. use the stored registry if valid;
3. otherwise use the bundled seed only when storage is missing;
4. never silently fall back to bundled data when stored data exists but is malformed.
